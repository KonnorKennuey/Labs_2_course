# Отчёт по лабораторной работе № 5

## 1. Цель и вариант

**Вариант:** 4.  
**Источник:** [Quotes to Scrape](https://quotes.toscrape.com/).  
**Точка входа варианта:** страницы `/tag/...`.  
**Маршрут:** каталог и теги → цитата → карточка автора.

Цель работы — создать полноценный Scrapy-проект с многоуровневым обходом, четырьмя звеньями Item Pipeline, пакетной записью в SQLite, вежливыми настройками, HTTP-кэшем, возобновлением через JOBDIR и анализом качества.

## 2. Ограничение источника и объём данных

В полном каталоге сайта находятся 100 уникальных цитат. Однако три цитаты не имеют ни одного тега:

- J.K. Rowling — «It is impossible to live without failing at something...»;
- Marilyn Monroe — «You believe lies so you eventually learn to trust no one but yourself.»;
- Ayn Rand — «The question isn't who is going to let me...».

Эти записи нельзя получить из точки входа `/tag/...`, установленной вариантом 4. Обход всех 137 обнаруженных тегов даёт:

- 97 уникальных цитат;
- 232 уникальные связи «цитата–тег»;
- всего 329 содержательных строк нормализованной БД.

Получить 300 уникальных цитат из данного источника невозможно. Поэтому требование объёма выполнено нормализованным представлением предметной области, а не искусственным копированием цитат. В таблице `quotes` бизнес-ключом остаётся обязательная пара `автор + цитата`, а связи с тегами хранятся отдельно в `quote_tags`.

Проект создан штатной командой `scrapy startproject` и имеет следующую структуру:

```text

├── quotes_crawler/

│   ├── pipelines.py
│   ├── settings.py
│   └── spiders/
│       └── quotes_tags.py
├── data/
│   ├── crawl.db
│   ├── items.jsonl
│   └── stats_*.json
├── jobstate/
├── quality/
│   ├── smoke_check.py
│   ├── baseline_summary.json
│   └── current_summary.json
├── requirements.txt
└── README.md
```

Ответственность разделена следующим образом:

| Компонент | Назначение |
|---|---|
| `items.py` | схема `QuoteItem` |
| `quotes_tags.py` | переходы, пагинация, селекторы, `cb_kwargs`, `errback` |
| `pipelines.py` | валидация, очистка, дедупликация, SQLite |
| `settings.py` | вежливость, повтор запросов, кэш и предохранители |
| `lab5_variant4.ipynb` | анализ статистики и качества |
| `smoke_check.py` | обнаружение деградации результата |

Использован обычный `scrapy.Spider`. Его явные методы лучше подходят для разных по смыслу переходов: каталог, страницы тегов и карточки авторов. `CrawlSpider` с общими правилами усложнил бы передачу контекста цитаты.

## 4. Паук и двухуровневый обход

### 4.1. Каталог и теги

Метод `parse` проходит 10 страниц общего каталога и извлекает ссылки всех тегов из карточек цитат. Повторные URL тегов автоматически исключаются dupefilter Scrapy.

Метод `parse_tag` обходит страницу и пагинацию отдельного тега. Из карточки извлекаются:

- текст цитаты;
- имя автора;
- ссылка автора;
- полный список тегов;
- исходный тег и URL страницы списка.

### 4.2. Карточка автора и `cb_kwargs`

Контекст передаётся в `parse_author` через `cb_kwargs`. Карточка автора добавляет:

- дату рождения;
- место рождения;
- биографию.

Один автор связан с несколькими цитатами, поэтому запрос страницы автора создаётся с `dont_filter=True`. Иначе Scrapy оставил бы только первый контекст для каждого автора. Повторные элементы затем корректно удаляются pipeline по бизнес-ключу.

URL автора нормализуется до HTTPS и завершающего `/`. Без этого сервер отвечал `308` на каждый запрос автора. После исправления число запросов снизилось с 617 до 385, время — примерно с 84 до 62 секунд.

### 4.3. Обработка ошибок

У каждого перехода задан `errback_request`. Он увеличивает:

- `network/errors`;
- `network/error_type/<тип>`.

В итоговом прогоне сетевых ошибок и повторов не было. Метод `closed()` сохранил статистику в `data/stats_final.json` и добавил причину завершения и независимое время прогона.

## 5. Item Pipeline

### 100 — ValidationPipeline

Проверяются цитата, автор, URL автора, теги, дата и место рождения, биография. Если поле отсутствует, увеличивается `dropped/missing_fields`, после чего вызывается `DropItem`.

### 200 — CleanPipeline

Pipeline:

- удаляет внешние кавычки и лишние пробелы;
- нормализует регистр тегов;
- удаляет повторные теги внутри записи;
- преобразует дату `%B %d, %Y` в ISO `YYYY-MM-DD`;
- вычисляет SHA-256 бизнес-ключа из нормализованных автора и цитаты.

Некорректная дата учитывается как `dropped/bad_date` и приводит к `DropItem`.

### 300 — DedupPipeline

Дедупликация выполняется по паре `автор + цитата`, а не по URL. В итоговом прогоне отброшено 135 повторных появлений цитат с разных страниц тегов.

### 400 — SQLitePipeline

Одно соединение открывается в `open_spider` и закрывается в `close_spider`. Записи буферизуются по 20 элементов и сохраняются через `executemany`.

Таблицы:

- `quotes`: 97 строк, первичный ключ `business_key`;
- `quote_tags`: 232 строки, составной ключ `(business_key, tag)` и внешний ключ на `quotes`.

Соединение внутри `process_item` не создаётся.

## 6. Настройки и вежливость

| Настройка | Значение | Обоснование |
|---|---:|---|
| `ROBOTSTXT_OBEY` | `True` | соблюдение правил площадки |
| `USER_AGENT` | учебный идентификатор | прозрачная идентификация |
| `CONCURRENT_REQUESTS` | 8 | общий умеренный предел |
| `CONCURRENT_REQUESTS_PER_DOMAIN` | 2 | ниже допустимого максимума 4 |
| `DOWNLOAD_DELAY` | 0,1 с | снижение нагрузки |
| `AUTOTHROTTLE_ENABLED` | `True` | адаптация к задержке сервера |
| `AUTOTHROTTLE_TARGET_CONCURRENCY` | 1,0 | один целевой активный запрос |
| `DOWNLOAD_TIMEOUT` | 20 с | защита от зависания |
| `RETRY_TIMES` | 2 | ограниченные повторы временных сбоев |
| `RETRY_HTTP_CODES` | 408, 429, 500, 502, 503, 504 | только временные ошибки |
| `DEPTH_LIMIT` | 25 | достаточно для 10 страниц и второго уровня |
| `CLOSESPIDER_ITEMCOUNT` | 300 | верхний предел элементов |
| `HTTPCACHE_ENABLED` | `True` | воспроизводимая отладка без повторной нагрузки |

`CLOSESPIDER_ITEMCOUNT = 300` не сработал, поскольку после дедупликации источник даёт только 97 цитат. Итоговая причина завершения — `finished`, то есть очередь запросов исчерпана. Сам предохранитель присутствует и исключает неконтролируемый рост при изменении сайта.

Второй запуск примерно в 2,1 раза быстрее. Различие числа items объясняется асинхронностью: после достижения `CLOSESPIDER_ITEMCOUNT` часть запросов уже находится в обработке.

## 9. JOBDIR и возобновление

Первый запуск с `JOBDIR=jobstate` был остановлен предохранителем, после чего остались:

- `requests.queue`;
- `requests.seen`;
- `spider.state`.

| Прогон | Время, с | Items | Дубли items | `dupefilter/filtered` | Поставлено на диск | Снято с диска |
|---|---:|---:|---:|---:|---:|---:|
| `job1` | 17,716 | 25 | 6 | 74 | 171 | 64 |
| `job2` | 16,928 | 23 | 22 | 21 | 72 | 91 |

После второго запуска демонстрационная БД содержит 44 уникальные цитаты и 115 связей. Это больше результата первого запуска и подтверждает продолжение сохранённой очереди. В `requests.seen` находятся 25 отпечатков запросов; значение `dupefilter/filtered = 21` второго запуска подтверждает работу сохранённой дедупликации URL.

## 12. Устойчивость к редизайну

| Селектор | Риск | Раннее обнаружение |
|---|---|---|
| `.quote` | переименование контейнера | резкое падение числа записей |
| `.text::text` | изменение вложенности текста | `dropped/missing_fields` |
| `a[href*='/author/']` | изменение схемы URL | `dropped/missing_author_link` |
| `.author-born-date::text` | изменение карточки автора | `dropped/missing_fields` или `dropped/bad_date` |
| `li.next a::attr(href)` | изменение пагинации | меньше 10 страниц и падение объёма |

Индексные XPath не используются. Основной механизм раннего обнаружения — статистические счётчики и smoke-check.

## 15. Выводы

1. Для разового обхода 500 страниц подходит Scrapy: проект требует начальной настройки, но даёт пагинацию, pipeline, статистику и контроль ошибок.
2. Для ежедневного обхода 40 000 страниц предпочтителен Scrapy с внешним планировщиком или Scrapyd: Python-код проще тестировать и масштабировать.
3. Для сотни страниц с последующей отправкой отчёта удобен n8n либо гибрид: n8n запускает Scrapy, ожидает завершения, читает сводку и отправляет уведомление.

## 16. Правовая и этическая оценка

Использована тренировочная площадка, предназначенная для обучения веб-скрейпингу. `ROBOTSTXT_OBEY=True`, параллелизм на домен ограничен двумя запросами, работают задержка и AutoThrottle. CAPTCHA, антибот-защита и реальные аккаунты не обходились.

Собранные биографические сведения относятся к публичным историческим данным учебного сайта. Реальные пользовательские аккаунты и контактные данные не обрабатывались. При переносе проекта на другой источник необходимо заново проверить условия использования, `robots.txt`, правовое основание обработки и применимость 152-ФЗ.
